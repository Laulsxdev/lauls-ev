### Gotcha

<!-- lore:019f0dcb-e215-7612-9712-52e157222142 -->
* **Convex auth schema requires authTables spread to avoid index errors**: Trap: Defining a Convex auth schema without spreading \`...authTables\` from \`@convex-dev/auth/server\` appears minimal but omits critical table definitions, causing missing index errors like \`Index authAccounts.providerAndAccountId not found\`. Fix: Always include \`...authTables\` in your schema to auto-create all auth tables with proper indices. This ensures auth operations function correctly.

<!-- lore:019f0dd2-c315-7c8d-a250-8147202d1e25 -->
* **Convex CLI multi-line environment variable trap**: Trap: Setting multi-line environment variables (e.g., JWT\_PRIVATE\_KEY PEM) via \`npx convex env set\` fails because the CLI argument parser splits on newlines and treats \`---\` sequences inside the value as flags, causing truncated values or 'unknown option' errors. The \`--from-file\` option also splits on newlines, storing only the first line, not the full multi-line value. Why it looks right: \`npx convex env set \<name> \<value>\` appears to accept any value, and \`--from-file\` seems like the natural choice for file-based values. Fix: Use stdin piping (\`pbpaste | npx convex env set KEY\` on macOS, \`Get-Clipboard | npx convex env set KEY\` on Windows) to preserve newlines and bypass the argument parser. Alternatively, use the Convex Dashboard UI to paste the value. After setting the env var, restart the Convex dev server (\`npx convex dev\`) to force the runtime to pick up the new value, as cached values may persist.

<!-- lore:019f0de8-7be9-791f-ba47-1024b544d339 -->
* **Convex signIn resolves before auth state syncs to queries**: Trap: \`signIn()\` from \`@convex-dev/auth\` resolves before auth state propagates to Convex queries. After \`await signIn(...)\`, \`useQuery(api.profiles.getCurrentUser)\` remains \`undefined\` (loading) then returns \`null\` (unauthenticated) for a window before auth state syncs. Code that immediately calls \`router.replace("/")\` lands on a page where queries see unauthenticated state, causing redirect loops back to \`/auth\`. Why it looks right: \`signIn\` returns a standard Promise; \`await\`ing it appears to mean authentication is fully settled. Fix: In the post-redirect page, handle the query loading state (\`profile === undefined\`) by waiting before checking authentication, or structure the sign-in flow to not query until auth state confirms.

<!-- lore:019f1809-6581-7416-abb2-2a7c922f8608 -->
* **Hardcoded passwords in auth and worker**: Passwords for admin and worker roles are hardcoded as '123' and not validated. This is a security risk. Fix: Implement proper password hashing and validation, or remove hardcoded credentials. Why it looks right: It might be for simplicity or testing, but in production, it's insecure and should be replaced.

<!-- lore:019f1809-6589-784e-bfda-d87cb2bfe3e0 -->
* **Missing profile on first login causes error**: When a user logs in with an email not in the profiles table, it shows 'No account found with this email. Sign up first.' Fix: Auto-create a profile entry on sign-in if it doesn't exist, ensuring smooth user flow. Why it looks right: The error suggests signing up, but users expecting to log in find it confusing; automation avoids this friction.

<!-- lore:019f1839-e844-7db7-a76e-c3517824d2bf -->
* **Netlify Environment Variables for Convex Deployment**: When deploying to Netlify with Convex, set only VITE\_CONVEX\_URL and VITE\_CONVEX\_SITE\_URL in Netlify environment variables. Do not set OPENROUTER\_API\_KEY in Netlify as it is only used by the Convex cloud AI action server and not required client-side. Why it looks right: One might include all env vars for consistency, but OPENROUTER\_API\_KEY is not needed in Netlify, avoiding unnecessary exposure and misconfiguration.

<!-- lore:019f180c-0aa7-7a08-8a7d-f87ad786b1af -->
* **Role selection ignored on existing email login**: When a user logs in with an email that already exists in the database, the role selected during login is not used; instead, the role from the database is applied, causing incorrect page redirection (e.g., admin page always opens even if worker is selected). Fix: Use the selected role from the login form, not just the database role, to ensure redirection matches user intent. Why it looks right: Prioritizing database records for consistency seems correct, but it ignores the user's explicit choice, leading to non-obvious bugs in role-based navigation.

### Pattern

<!-- lore:019f11d3-d126-7da1-922e-96d66a09b40d -->
* **Dashboard metrics calculation logic**: Active vehicles: count vehicles with status === 'active' from vehicles table. Drivers on roster: count drivers with rosterStatus === 'on\_roster' from drivers table. Trips logged: count of documents in trips table. Energy consumed: sum of energyConsumed field from trips. Average battery health: average of batteryHealth from vehicles where batteryHealth > 0. Geofence breaches: count alerts with alertType === 'geofence\_breach' from alerts table.

<!-- lore:019f0ddc-a530-7ab7-8233-77942c9dd01a -->
* **Default employee level to 'full' when unspecified**: When displaying an employee's level in the UI (e.g., in authentication or user profile), if no level is specified, default to displaying 'full'. This is a business rule for the fleet management platform.
